# PROJECT_RULES.md: Конвенции и правила для ИИ

## 🛑 Anti-Hallucination

1. **Не выдумывай API.** Если функции нет в `PROJECT_INDEX.md`, скажи об этом.
2. **Не придумывай поля БД.** Сверяйся с `schema.prisma`.
3. **Не выдумывай пути.** Если не уверен, где лежит файл, спроси.
4. **Честность важнее скорости.** Если не знаешь — скажи.

## 🚨 Главное правило: Не дублируй UI!

**Перед созданием нового компонента ОБЯЗАТЕЛЬНО сверься с `PROJECT_INDEX.md` и `DESIGN_SYSTEM.md`.**

- **Пример из прошлого:** ИИ предлагал создать новый heatmap для админки, хотя уже есть `YearHeatmap` и `AdminHeatmap`. Это ошибка.
- **Если функционал уже есть — используй существующий компонент.** Если он не подходит — расширь его пропсами, а не пиши с нуля.
- **Если ты видишь дублирование в коде — предложи вынести его в общий компонент** (в `components/ui/` или `lib/`).

## 🏗️ Архитектурные правила

1. **Server Components по умолчанию.** `"use client"` — только для интерактива (useState, onClick, useTransition).
2. **Мутации только через Server Actions.** Новые API-роуты не создавать (исключение: `app/api/search/route.ts`).
3. **Soft Delete.** Физическое удаление запрещено. Используем `deletedAt` (см. `deletePerson`, `deleteCharacter`).
4. **Связи строго по `id`.** Не по текстовым именам.
5. **Защита от дублей.** Всегда проверяем не только основное имя, но и альтернативные (см. `createPerson` и `createDrama`).
6. **Все мутации логируются в `AdminLog`.** После каждого `create/update/delete` пишем лог с `action`, `entityType`, `entityId`, `entityName`. Флаг `isPublic` ставим `true`
7. **Работа с миграциями БД.** База данных управляется строго через `prisma migrate`.
   - ✅ **Правильно:** `npx prisma migrate dev --name <краткое_описание>` — создает файл миграции и применяет его к базе.
   - ❌ **Запрещено:** `npx prisma db push` — используйте только в крайних случаях для быстрого прототипирования (он ломает историю миграций).
   - ⚠️ **Важно:** Если Prisma просит "reset" из-за расхождения схемы (drift), не соглашайтесь. Нужно сделать `prisma db push` (чтобы синхронизировать базу), затем удалить папку `migrations`, сгенерировать новую базовую линию (`migrate diff`) и пометить её применённой (`migrate resolve --applied 0_init`).только для значимых событий (создание, удаление, завершение).

## 🖼️ Правила работы с изображениями

1. **Всегда `next/image`.** Обычный `<img>` запрещён — только `<Image>` из `next/image`.
2. **Внешние домены — только из белого списка.** Все `remotePatterns` живут в `next.config.ts`. Если нужен новый источник картинок — сначала добавь домен в конфиг, потом используй.
3. **Текущий белый список:**
   - `i.mydramalist.com`, `s.mydramalist.com` — MyDramaList.
   - `kinopoiskapiunofficial.tech`, `st.kp.yandex.net`, `avatars.mds.yandex.net` — Кинопоиск.
   - `raw.githubusercontent.com` — статика из репозитория (маскот).
   - `i.ytimg.com`, `i.scdn.co` — обложки YouTube / Spotify.
   - `static.tvmaze.com` — импорт TVmaze.
   - `i1.sndcdn.com`, `**.sndcdn.com`, `vk-cdn.net`, `**.vk-cdn.net`, `mycdn.me`, `avatars.yandex.net` — обложки аудио (SoundCloud, VK, Яндекс Музыка).
4. **Обязательные пропсы:** `alt` (для доступности) и `width/height` **или** `fill` + обёртка `relative`.
5. **Iframe не требует `remotePatterns`.** SoundCloud, VK, Yandex, YouTube-плееры вставляются обычным `<iframe>` — настройка `images` на них не влияет.
6. **Не отключай оптимизацию** (`unoptimized={true}`) без причины — это ломает смысл `next/image`.

## 🎨 UI-правила

1. **Только семантические токены** (`bg-surface`, `text-accent`, `border-border`). Никаких `bg-zinc-800`!
2. **Используй `components/ui/`.** Не пиши кастомные кнопки, меню или инпуты (см. `Button`, `DropdownMenu`, `SearchableSelect`).
3. **Стиль:** Bento-сетка, скругления `rounded-2xl`, шрифты `text-sm`, иконки `w-4 h-4`.
4. **Hover-эффекты:** Все интерактивные элементы должны иметь плавные переходы и тултипы.
5. **Перед версткой новой страницы сверься с `PAGE_RECIPES.md`.**
6. **Никаких эмодзи в коде!** 🚫
   - Вместо 🎭, 🎬, 👤 и других смайликов используем только векторные иконки из `lucide-react` (или `react-icons`, если нужен логотип бренда).
   - Иконки должны иметь классы `w-4 h-4` или `w-5 h-5` и цвет `text-accent` или `text-muted`.
   - **Исключение:** `🔴`, `🟡`, `⚠️` в **комментариях** — это осмысленный маркер механики заполненности карточек. Их оставляем.
   - **Тосты:** эмодзи не используем. Смысловые иконки передаём через `icon`-проп Sonner: `toast.success("текст", { icon: <Sparkles className="w-4 h-4" /> })`. Цвета тостов настроены глобально через `richColors` в `app/layout.tsx`.
7. **Только прямоугольные фото и постеры!** 📸
   - Круглые аватарки (`rounded-full`) запрещены для актеров, персонажей и ролей в касте.
   - Всегда используем пропорции постера: `aspect-[2/3]` (или жесткие размеры `w-14 h-20`), объект-фит `object-cover` и мягкие скругления `rounded-lg`, `rounded-xl` или `rounded-2xl`.

## 📝 Комментарии и JSDoc (Обязательно!)

1. **JSDoc для функций и компонентов:** Каждая экспортируемая функция или компонент в `lib/` и `components/ui/` ОБЯЗАН иметь JSDoc-комментарий. Это не для человека, а для скрипта `ts-morph`, который будет собирать `PROJECT_INDEX.md`.

   **Формат:**

   ```typescript
   /**
    * Склонение русских слов по числительному.
    * @example plural(5, 'серия', 'серии', 'серий') // 'серий'
    * @dontDuplicate Не писать "серия/серии/серий" вручную в компонентах.
    */
   export function plural(n: number, one: string, few: string, many: string): string { ... }
   ```

## 📝 Формат ответа ИИ

1. **Сначала сверься с `PROJECT_INDEX.md`.** Если функционал есть — используй его.
2. **Не пиши полные файлы.** Давай точечные патчи: `Было:` -> `Стало:`.
3. **Не пересказывай правила.** Без вступлений и резюме.
4. **Обновление индекса:** Если ты предлагаешь новый файл или функцию, которой нет в `PROJECT_INDEX.md`, ты ОБЯЗАН выдать в конце ответа блок **`[ОБНОВИТЬ ИНДЕКС]`** в формате Markdown с четкой инструкцией (в какой раздел вставить) и готовым текстом для копирования.

   **Формат блока `[ОБНОВИТЬ ИНДЕКС]`:**

   ````markdown
   ### [ОБНОВИТЬ ИНДЕКС]

   **Куда вставить:** В раздел `components/ui/` (после `button.tsx`)
   **Что вставить:**

   ```markdown
   ### form-input.tsx

   Универсальный компонент текстового поля.
   export FormInput: (props: React.InputHTMLAttributes<HTMLInputElement>) => JSX.Element
   client: no
   ```
   ````

## ⚠️ Важные нюансы из текущего кода

- **`getDramaStatus` / `getPersonStatus` / `getCharacterStatus`** — используются для проверки "позеленения" карточки. Если статус стал `green` — пишем лог `*_COMPLETED`.
- **`revalidatePath`** — обязательно вызывать после мутаций для обновления кеша (главная, /library, /dramas/[id], /admin/\*).
- **`detectLanguage`** — вынесена в `lib/language-utils.ts`. Используется для альтернативных названий и имен.
- **`normalizeTitle`** — вынесена в `lib/drama-utils.ts`. Очищает название от лишних символов.
